# CMS 与前台内容契约修复

## 目的与用户可见结果
修复后台正文编辑器无法加载及退出编辑页时报错的问题，消除 CMS 字段与前台实际展示之间的歧义，使维护者能够明确完成活动置顶、友情链接、指导老师、QQ群和换届成员维护。

## 范围与明确不做
覆盖 Vditor 生命周期、Decap 配置、Astro schema、数据查询、前台展示、测试与维护文档。保留纯静态站、Decap CMS 和 GitHub Pages 架构；不删除现有内容，不改写共享历史。

## 当前事实与相关文件
- 后台入口：`src/admin/main.tsx`、`public/admin/config.yml`。
- 内容契约：`src/content.config.ts`、`src/lib/content.ts`、`src/data/*.yml`。
- 消费页面：`src/pages/index.astro`、`src/pages/about.astro`、`src/pages/team-history.html.ts`、`src/components/Footer.astro`。
- 生产由 `main` 自动部署；当前工作分支为 `develop/astro-cms`。

## 验收标准
- 编辑正文时 Vditor 可见；初始化失败时显示可编辑 Markdown 文本框。
- 进入并退出编辑页不抛出 Vditor `destroy` 的 `element` 异常。
- CMS 每个可编辑字段均有明确前台消费者或明确说明；无效开关被修正或移除。
- 首页置顶/显示、老师、链接、联系方式和成员届次行为有自动测试或构建验证。
- 桌面与移动端页面及 CMS 编辑流程完成验证。

## 分阶段步骤
1. 审计字段、schema、查询和页面消费者，记录缺口。
2. 修复编辑器生命周期和文本回退，补回归测试。
3. 对齐前后台字段与展示，补充换届维护能力和说明。
4. 执行类型、内容、构建、端到端及视觉验证。
5. 更新内容模型、运维说明和进度记录，提交自包含 commit；仅在满足生产门禁后按既有流程上线。

## 进度（带时间）

## 发现与证据
- `showOnHomepage` 与 `featuredActivityLimit` 原先未参与首页活动选择；首页直接读取全部未归档活动。
- `featured` 原先仅影响全局活动排序；修复后仍作为候选排序依据，并由每个方向选择排序最前项。
- 指导老师已在关于页消费，联系方式已在关于页和页脚消费，QQ 群可以后台更换。
- 普通友情链接原先无消费者，只有仓库用途进入首页；现已补充关于页相关链接，页脚用途也进入页脚。
- 本届执委原先取排序后的最新年份，虽能自动换届但无明确控制且拼写错误难发现；现改为 `organization.currentCohort` 并增加内容校验。
- Vditor 在异步初始化完成前退出时，实例存在但内部 element 尚未建立，直接 `destroy()` 可复现堆栈所示失败模式。

## 决策记录
- 不以删除后台字段掩盖前台缺口；优先让组织运营需要的数据在合适页面可见。
- 删除无效的首页活动数量字段，因为首页视觉固定为四个方向；保留并明确活动级显示/优先开关。
- 本届届次使用站点设置显式指定，历史档案继续从成员数据自动分组，兼顾可控切换和历史保留。
