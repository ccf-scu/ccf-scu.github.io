# 后台页面化重构与外部图床媒体中心

> 状态：实现完成，待生产发布验证
>
> 建立日期：2026-08-23
>
> 实施约束：本文件只记录下一阶段开发计划，不代表已经修改、验证或发布任何业务代码。

## 目的与用户可见结果

重构 `/admin/` 的内容组织、字段和发布入口，使非技术维护者按照前台页面完成维护，而不必理解底层 Markdown/YAML 文件如何拆分。重构完成后：

- 首页公告、四个活动展示位、三项荣誉及首页文案在“首页管理”语境内维护；
- 活动编辑只描述活动自身，首页选取逻辑全部移至首页设置；
- 活动中心保留独立、含义明确的置顶能力；
- 后台只显示一个“待发布”暂存入口，每条内容仍使用 Decap 原生的独立暂存和独立发布，不引入发布批次；
- 仓库媒体上传被自定义外部图床媒体中心替代；维护者可在本机配置通用 HTTP 图床、上传并选图，也可直接粘贴完整图片 URL；
- 已发布内容引用的图片自动进入全员可见的共享媒体库，历史 `/uploads/...` 图片无需迁移；
- CMS 中每个业务字段都有明确的前台消费者、维护用途或兼容理由，不再出现“可以填写但前台永远不显示”的字段。

本次不重新设计 Decap 的视觉语言。只调整信息架构、导航命名、字段分组、控件、工作流入口及必要的交互反馈。

## 目标数据模型与迁移

### 首页显式引用

在 `src/data/homepage.yml` 增加稳定引用，具体字段名在实现时以 schema 审查为准：

```yaml
featuredContent:
  announcements:
    - <announcement-entry-id>
  activities:
    academic: <activity-entry-id>
    competition: <activity-entry-id>
    tutoring: <activity-entry-id>
    career: <activity-entry-id>
  honors:
    - <honor-entry-id>
    - <honor-entry-id>
    - <honor-entry-id>
```

- 引用使用发布后稳定的 entry ID/文件 slug，不使用可能变化的标题；
- 公告允许 1–10 个且不可重复；荣誉必须恰好 3 个且不可重复；四个活动槽位均必填；
- 活动引用必须存在、未归档并匹配槽位类别；`organization` 永远不合法；
- 公告引用必须存在且 `visible: true`；荣誉引用必须存在且 `visible: true`；
- 如果被首页引用的内容后来隐藏、归档、改类或删除，内容校验和构建必须失败并给出可操作错误，不允许静默用其他内容补位；
- 首页按引用顺序渲染，不再根据内容级 `featured` 字段二次排序。

### 活动置顶

- 将活动 `featured` 迁移为语义明确的 `pinned`（最终命名可在实现时统一，但 CMS 标签固定为“活动中心置顶”）；
- 迁移时将现有 `featured: true` 等价转换为 `pinned: true`，保留目前活动列表的置顶意图；
- `src/lib/content.ts` 的活动中心排序为：先排未归档内容，置顶优先，组内按开始时间倒序；
- 首页完全忽略 `pinned`，只使用首页四个显式引用；
- 删除所有活动的 `showOnHomepage`，并从 schema、CMS、校验、测试和文档中移除。

### 公告和荣誉

- 删除公告 `featured`；首页公告由首页引用列表及其顺序决定；
- 删除 `homepage.announcementLimit`；
- 删除荣誉 `featured`；首页荣誉由首页固定三项引用决定；
- 删除荣誉 Markdown 正文及 CMS `body` 字段；迁移前检查现有文件是否含非空正文并生成报告，若存在真实资料不得静默丢弃，需先由负责人决定迁入何处；
- 保留公告可选正文，因为公告可能通过链接或预览使用；实现审计必须再次确认其消费者，若仍无消费者则在迁移报告中单独提出，不擅自删除；
- 成员 `profileConfirmed`、活动 `sourceUrl` 等内部字段在字段消费清单中标注用途。只有确认既无前台消费、又无维护或迁移价值后才能移除。

### 首次迁移的确定性规则

迁移脚本必须可重复运行并先输出 dry-run 报告：

- 首页公告初值使用迁移前生产逻辑所得结果：可见、未失效，先旧 `featured`、再按发布时间倒序，并按旧 `announcementLimit` 截取；
- 四个首页活动初值使用迁移前首页实际展示的四项结果，每个固定方向一项；
- 首页荣誉初值使用迁移前首页实际展示的三项结果，包括既有按标题去重行为；
- 现有活动 `featured` 映射为活动中心 `pinned`；
- 迁移报告列出所有将删除的字段、无法解析的引用、空槽位和非空无效正文；
- 只有 dry-run 结果经人工核对后才写入文件；迁移不得物理删除内容文件或图片。

## 外部图床与共享图片中心设计

### 产品语义

- 图片中心不是图床文件管理器，而是“本站已经使用的图片索引 + 当前浏览器的上传入口”；
- 所有人都可浏览、搜索、预览和复用已发布内容引用的图片，无需拥有图床 Token；
- 用户上传新图片或直接粘贴图片 URL 后，该图片立即进入当前浏览器的“最近使用”；
- 内容保存到待发布时，图片随条目暂存，但不会提前污染全员共享索引；
- 条目正式发布并完成静态构建后，图片从已发布内容中被自动收集，进入全员共享媒体库；
- 相同 URL 精确去重；同一图片可记录多个使用位置和多个替代文本；
- 图片不再被任何已发布内容引用时标记为未使用或从默认结果中隐藏，不删除图床原文件；
- 直接粘贴 URL、图床上传所得 URL、Markdown 图片和历史 `/uploads/...` 路径遵循同一收集规则。

### 图片索引

构建期生成不含秘密的静态索引，例如 `media-index.json`。实现时应从以下已发布来源提取：

- 活动封面；
- 成员、指导老师照片；
- 荣誉图片；
- 首页、全站或 SEO 设置中的图片字段；
- Markdown 标准图片语法中的 URL；
-仍被内容引用的 `/uploads/...` 历史资源。

每个索引项至少包含：

- 原始 URL；
- 推断出的文件名；
- 来源类别（活动、成员、老师、荣誉、正文、全站或历史）；
- 引用内容的稳定 ID、标题和后台编辑入口；
- 可取得的替代文本；
- 首次发现信息若无法在无状态构建中可靠保存，则不伪造时间，可改为当前内容的发布时间或省略；
- 是否为站内历史资源；
- 当前引用数量。

索引生成必须解析标准 Markdown 图片节点，而不是用易误判代码块和转义文本的简单正则。索引是可再生构建产物，不作为新的内容真源，不为每次上传额外创建 PR。

### 本地图床配置

首期只支持一个当前启用的通用 HTTP 图床配置：

- 图床显示名称；
- `multipart/form-data` 上传接口 URL；
- 文件字段名，默认 `file`；
-认证 Header 名称及 Token/值；
- 可选的固定表单字段；
- 从 JSON 响应读取最终图片 URL 的字段路径，例如 `data.url`；
- 测试配置/测试上传；
- 清除本地配置和凭据。

非敏感配置可保存在 `localStorage`。Token 默认只进入 `sessionStorage`；用户主动勾选“在本机记住凭据”后才可进入 `localStorage`，界面必须明确提示仅在私人、受信设备使用。字段不得进入 Redux 调试输出、URL、Git、日志、错误详情或截图。

“用户自行定义图床”表示可配置上述通用协议参数，不表示执行任意 JavaScript、任意请求模板或绕过浏览器 CORS。目标图床必须允许 `/admin/` 所在来源发起跨域上传。配置测试需区分：CORS 拒绝、网络错误、HTTP 错误、JSON 解析失败、响应路径错误和成功但 URL 非法。

### CMS 控件

- 注册自定义外部图片控件和自定义媒体库集成；普通图片字段可选择共享图片、上传新图或粘贴 URL；
- Markdown 保留原生编辑能力，并提供插入共享图片 URL/上传后插入的入口；若 Decap 原生 Markdown 工具栏无法无补丁扩展，则保留标准 Markdown 粘贴方式并在图片中心提供“一键复制 Markdown”；
- 图片字段不再调用仓库媒体上传；应评估移除全局媒体入口、旧 `media_folder` 行为和现有 Decap 媒体补丁；
- 最近使用列表只保存在当前浏览器，可包含尚未被内容引用的上传结果，并提供清空功能；
- 全员共享列表首期支持按来源分类、标题/文件名/URL 搜索、预览、复制 URL、查看引用位置；
- 不提供删除图床原文件、远程重命名、远程移动或多层手工分类。

### URL 与内容安全

用户确认“不做图床域名白名单或归属校验”，因此不限制到指定图片域名。但仍必须保留最低协议和输出安全边界：

- 允许现有站内绝对路径和外部 `https://` 图片；生产 HTTPS 页面不得新增会被浏览器拦截的 `http://` 混合内容；
- 拒绝 `javascript:`、`data:text/html`、`file:` 等可执行或本地协议；是否允许受控 `data:image/*` 应在实现前安全评估，默认不允许持久化；
- 上传前在浏览器检查文件大小、声明 MIME 和可解码性；限制值在实施时写入配置、文档和测试；
- 外部图床可能失效、限流、替换内容或追踪访客，维护手册必须说明版权、隐私、稳定性和防盗链责任；
- 前台不加载图床上传 SDK、Token 或 CMS bundle，只加载最终图片 URL。

## 验收标准

### 信息架构和字段

- 后台入口按目标页面连续排列，维护者能从标签和说明判断改动影响哪个前台页面；
- 首页同一设置入口可完成公告顺序、四个活动槽位和三项荣誉的编排；
- 四个活动槽位全部必填、类别正确且不接受 `organization`；
- 活动编辑页不再出现“首页显示”或“首页优先”，只保留“活动中心置顶”；
- 多个活动可同时置顶，置顶组内按开始时间倒序；已结束活动可置顶；归档内容不显示；
- 荣誉编辑页没有正文和首页精选；公告没有首页置顶；首页没有公告数量；
- 每个 CMS 字段均在字段消费清单中有前台消费者或明确维护理由。

### 工作流

- 新建或编辑内容后可以保存到唯一的“待发布”入口，正式站内容不变化；
- 待发布列表不要求维护者在草稿、审核中、待审核等状态间移动；
- 任一有写权限的维护者可逐条发布；发布一条不会连带发布其他条目；
- 后台不提供预约发布、退回暂存、取消发布或批次发布；
- 发布后的 Git 分支/PR 清理、构建触发和失败反馈保持可追踪；
- Git 历史仍可用于仓库级回滚，但后台不增加回滚按钮。

### 图片中心

- 未配置图床时仍可浏览共享图片、选择历史图片和直接粘贴 URL；
- 配置兼容的 HTTP 图床后可测试连接、上传图片并自动取得 URL；
- 上传成功后图片进入本机最近使用，并能直接填入普通图片字段；
- 直接粘贴的 URL 同样进入本机最近使用；
- 待发布内容引用的图片不会提前出现在其他用户的共享库；正式发布并重新构建后会出现；
- 活动、成员、老师、荣誉和 Markdown 中的已发布图片均能被索引；
- 相同 URL 不生成重复卡片，引用位置能够聚合展示；
- 其他维护者无需图床 Token即可查看、复制和选择共享图片；
- Token 不出现在仓库 diff、构建产物、URL、错误日志或测试截图；
- 清除本地配置后上传能力关闭，但已发布图片仍可浏览和复用；
- 图床 CORS 拒绝、超时、错误响应、错误 JSON 路径和无效 URL 均有中文可操作提示；
- 后台没有删除图床原文件的入口。

### 兼容性和质量

- 所有现有 `/uploads/...` 图片继续显示，不进行迁移；
- 已有 34 个静态页面及前后台 bundle 隔离不回归；
- 内容 schema、CMS 配置、迁移脚本和页面查询使用一致字段；
- 首页、活动列表、活动详情、关于、档案、搜索和后台在桌面及至少 390px 移动视口通过验证；
- JavaScript 或图床上传失败不影响已发布前台内容；
- 根路径和 `SITE_BASE=/preview-site/` 子路径构建均通过。

## 风险与回滚

- **Decap 内部 API 风险**：单一待发布界面和媒体库可能触及版本相关扩展点。使用公开注册 API优先；不得避免版本守卫；升级 Decap 前必须跑 CMS E2E。
- **图床兼容风险**：不同服务的字段、认证、CORS 和响应格式差异大。以受限通用协议、测试连接和清晰错误为边界，不宣称全兼容。
- **凭据风险**：长期浏览器存储可能被同源脚本或失陷设备读取。默认只存会话，长期记住必须主动选择并提示风险；推荐受限、可撤销上传 Token。
- **外部图片风险**：防盗链、失效、内容替换、性能和隐私不受本站完全控制。保留 URL 审计和引用列表，文档要求选择稳定 HTTPS 图床。
- **引用完整性风险**：显式首页引用可能在内容归档或改类后失效。schema/构建硬失败优于静默替换，并提供具体修复路径。
- **迁移风险**：删除旧字段可能改变当前首页或活动列表。迁移以生产算法生成初值、dry-run 对照和可重复脚本控制。
- **并发风险**：首页设置仍是单个 YAML 文件，多人同时编辑可能产生 Git 冲突。待发布界面必须显示冲突；维护手册建议同一时间只由一人编排首页。
- **共享索引时效**：图片只有在内容发布并重新构建后才对其他人可见，这是已确认产品语义；构建失败时不得假称已经共享。

回滚以本任务自包含 commit 为单位执行 `git revert`，不使用 reset 或改写历史。迁移脚本在写入前生成报告；旧字段兼容读取至少保留一个受控迁移窗口，待新内容、构建和生产验证通过后再删除。现有 `/uploads/...` 资源始终保留，因此回滚无需恢复图片文件。
