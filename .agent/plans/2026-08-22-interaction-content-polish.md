# 补齐 ccfweb 动效、内页版式与后台可编辑能力

## 目的与用户可见结果

在已完成的 ccfweb 视觉母版迁移基础上，补回原母版最有辨识度的线状共振、无限球体、活动切片、档案叠卡和仓库面板动效；修正内页满屏贴边、详情正文偏左、搜索独占页面等体验问题；清理仅供开发者阅读的临时说明；并让首页主要中文内容可由 Decap CMS 后台维护。

完成后，首页不仅在静态截图上接近 `../ccfweb`，实际滚动、指针移动、切换栏目和聚焦控件时也应具有相近的丝滑反馈。活动、关于、档案与详情页必须使用有明确最大宽度和两侧留白的内容容器。维护者可以在后台修改面向访客的首页文案、公告和多项友情链接，无须编辑 Astro 模板。

本计划记录用户提出的全部需求和后续维护操作。计划本身不代表发布授权；实现阶段仍不得 push、部署或修改生产分支。

## 范围与明确不做

### 本次范围

1. 删除首页 Hero 中“移动即产生共振，无需点击”提示文字。
2. 按 `../ccfweb` 最终版本补回 Hero 背景线状动画，并保留指针/触摸响应。
3. 补回 About 左侧无限球形/轨道的持续动画。
4. 补回活动切片仪的平滑切换、叠卡位移、层级和光影过渡。
5. 补回成果档案右侧栏目卡片的入场、叠放和切换反馈。
6. 补回开源仓库预览框的入场与内部行项目动画。
7. 删除开源模块中的“分会官方网站源码与内容档案由 Git 管理，公开内容的每次修改都可追溯。”，在同一位置突出真实 GitHub 链接，行为与母版一致。
8. 为关于、活动、档案、搜索兼容页和活动详情增加统一内容容器与响应式留白，解决内容铺满屏幕或长期偏在左侧的问题。
9. 从 Header 删除 `CN` 控件。
10. 将导航搜索改为全屏搜索面板：点击搜索入口后打开独立视觉层，在其中输入并即时显示结果。
11. 保留 `/search/` 作为无 JavaScript、旧链接和直接访问的兼容入口，但不再把它表现为主要独立导航页面。
12. 删除“资料来自旧站，图片已经进入受控迁移清单”等仅供负责人或开发者阅读、不应面向访客展示的说明，并全站审计同类文案。
13. 放大首页 `NOTICE` 标签及“新版主页正在建设 · 新站将在保留历史资料的基础上，提供更清晰的活动浏览和长期维护能力。”正文，提高视觉层级。
14. 扩展首页 CMS 字段，使主要访客文案、按钮和链接可后台修改。
15. 保持友情链接为可添加多项的列表，并为 GitHub/代码仓库链接增加稳定、可配置的用途标记。
16. 保留页脚年份自动生成机制，并在维护文档中说明它在每次静态构建时更新。

### 明确不做

- 不整体复制 ccfweb 约八千行、包含多轮废弃原型的 CSS；只迁移当前母版使用的动画逻辑。
- 不引入 WebGL、大型动画框架或常驻服务；优先使用 Canvas、CSS transform/opacity 和轻量原生脚本。
- 不把 Decap、Vditor 或 OAuth bundle 加载到公开页面。
- 不删除 `/search/` 路由，不破坏旧链接和项目子路径部署。
- 不把纯装饰英文编号、坐标和动画参数放进 CMS，以免内容维护误伤布局。
- 不在本阶段配置真实 OAuth、push、创建 PR 或部署。

## 首页后台可编辑边界

### 实现后允许后台修改

- Hero 眉题、主标题、副标题、主次按钮文字和链接。
- About 主标题、介绍、三项原则的中文标题与说明、引用文字。
- 活动章节标题、说明以及四个活动方向的展示文案；具体代表活动继续来自活动集合。
- 成果章节标题、说明和时间轴文字；荣誉卡片继续来自荣誉集合。
- 开源章节标题、GitHub 按钮文字和目标仓库链接。
- Join 标题、说明、按钮文字和路径说明。
- NOTICE 公告标题、摘要、显示状态和有效期。
- 多项友情链接的名称、URL、类型、排序、显示状态和用途。

### 继续由代码控制

- 章节编号、坐标、状态索引等装饰性技术标签。
- 动画速度、缓动、粒子/线段数量、视觉层级和响应式断点。
- HTML 语义、无障碍属性、内容容器和组件结构。
- 数据安全校验、基础路径处理和前后台 bundle 隔离。

### 字段迁移策略

先在 `src/data/homepage.yml` 增加结构化字段，再同步 `src/lib/site.ts` 的 Zod schema 与 `public/admin/config.yml`。现有值作为默认迁移内容写入 YAML，不允许因为字段升级导致构建失败或首页空白。数组字段应限制合理数量，例如三项原则固定为 3 项、活动方向固定为 4 项；主要栏目不得接受任意 HTML。

友情链接继续使用列表而非单个字段。每项至少包含 `name`、`url`、`category`、`order`、`visible`，并新增稳定用途字段，例如 `placement: general | repository | footer`。首页开源模块按用途读取代码仓库链接，不再通过名称正则猜测。多个普通友情链接可以并存、排序和隐藏。

## 维护者简易操作

### 修改首页文字

1. 进入内容后台。
2. 打开“站点设置 → 首页设置”。
3. 在 Hero、分会介绍、活动、成果、开源和招募分组中修改文字或链接。
4. 保存为草稿并预览，确认换行和按钮目标后再发布。

首页活动图片、标题和日期仍通过“活动”集合维护；荣誉图片和标题通过“荣誉与成果”集合维护；NOTICE 通过“公告”集合维护。

### 添加多个友情链接

1. 打开“站点设置 → 友情链接”。
2. 在“友情链接列表”中点击添加，可连续创建多项，不限于一个。
3. 填写名称、HTTPS 地址、类型、用途、排序和显示状态。
4. GitHub 仓库应选择“代码仓库”用途；普通组织链接选择“普通链接”。
5. 发布后由静态构建更新页面。

### 页脚年份

维护者无需手工修改 `© 2026`。页脚在构建时读取当前年份；进入新年份后，任意一次后台发布或站点重新构建都会自动更新。如果跨年后从未重新构建，线上静态文件会暂时保留上次构建年份，这是静态站的正常行为。

## 动效实现原则

### Hero 线状共振场

- 重新审计 `../ccfweb/script.js` 中当前 Hero 使用的线段、节点、指针影响半径和衰减方式。
- 使用独立、可销毁的 Canvas 增强层，按照设备像素比控制清晰度并限制最大 DPR。
- 页面不可见时暂停；窗口变化时节流重算；不得阻塞按钮、文本选择或页面滚动。
- Canvas 失败或 JavaScript 禁用时保留现有网格、光晕和完整文字。

### 无限球形/轨道

- 使用 transform/opacity 驱动轨道旋转、尺度呼吸和关键词漂移，避免高频布局计算。
- 动画应接近母版的缓慢连续运动，不能快速旋转造成眩晕。
- 装饰容器保持 `aria-hidden`，不进入键盘顺序。

### 活动切片仪

- 切换时同步左侧文字、活动卡片、背景色晕、索引和 Tab 状态。
- 卡片使用 transform、opacity、filter 和层级过渡形成叠页滑动；禁止通过定时器隐藏核心内容。
- 鼠标、触摸和键盘均可操作，`aria-selected` 与可见内容必须同步。

### 成果档案卡

- 卡片在进入视口时做一次轻量叠放展开，悬停/聚焦时提供局部前移反馈。
- 使用内容集合的真实荣誉卡，不用动画复制或硬编码虚假内容。

### 开源仓库面板

- 整体进入时使用短距离位移和淡入；文件行按小幅延迟依次出现。
- 悬停/聚焦文件行时仅做轻量横移和蓝色提示，保持文本清晰。
- 左侧说明文字删除后，由真实 GitHub 链接按钮承担主要动作；按钮不能是空链接。

### 减少动态与性能

- `prefers-reduced-motion: reduce` 下关闭持续旋转、线场响应、叠卡飞入和逐行延迟，仅保留即时状态切换。
- 动画只改变 transform/opacity 等合成属性；Canvas 使用 `requestAnimationFrame`，离屏或隐藏标签页时暂停。
- 360/390/430 宽度下主动降低线段和节点数量，避免低端手机耗电和掉帧。

## 搜索面板设计

- Header 中保留“搜索”入口，但点击后打开覆盖当前页面的全屏 `dialog`/搜索层，而不是立即导航到独立页面。
- 面板包含明确标题、搜索框、关闭按钮、结果数量和活动/成员结果列表；打开后焦点进入输入框，Escape 关闭，关闭后焦点回到触发按钮。
- 使用当前本地搜索索引，不增加服务端搜索或外部请求。
- 为避免重复维护，将索引生成和前端结果渲染提取为共享模块/组件，搜索面板与 `/search/` 兼容页共用。
- 无 JavaScript 时 Header 搜索链接仍指向 `/search/`；直接访问 `/search/?q=关键词` 继续有效。
- 打开面板时锁定背景滚动，并正确设置可访问名称；不得让背景链接仍可被键盘聚焦。

## 内页容器与内容清理

- 不对所有 `.section` 全局加宽度，因为首页章节内部已有 `.container`；为内页增加明确的 `.page-section`/`.page-container` 结构。
- 桌面正文最大宽度遵循 1240px 容器，两侧至少 32px；长正文主体控制在约 720—820px，详情侧栏约 280—320px。
- 活动详情的正文与侧栏整体居中；移动端改为单列并保持约 16px 页面留白。
- 活动卡片、荣誉卡片和成员卡片不得贴屏幕边缘；超宽图片、表格和代码块必须在自身容器内滚动或缩放。
- 全站搜索并删除仅面向维护者的措辞，包括但不限于“资料来自旧站”“进入受控迁移清单”“待维护者补充”“上线前核对”等。需要保留的核验信息放入 `docs/` 或内容 frontmatter，不显示给访客。

## NOTICE 视觉要求

- 保留公告的动态数据来源，不把当前文案硬编码进首页。
- 桌面正文从当前 `0.85rem` 提升到约 `1.05—1.15rem`，NOTICE 标签同步提升并增强字重/颜色对比。
- 增加上下内边距和标签与正文的节奏，可使用细线或小型蓝色状态点，但不做抢占主标题的警告横幅。
- 多条公告必须纵向排列；移动端允许自然换行，标签不能挤压正文。

## 验收标准

1. 首页不再出现“移动即产生共振，无需点击”和 Header `CN`。
2. Hero 在线状场、指针响应和静态回退方面与 ccfweb 母版明显一致。
3. 无限球体、活动切片、成果叠卡和仓库预览均有连续或触发式动画；减少动态模式下全部稳定可读。
4. 活动切片使用鼠标、触摸、Tab/Enter/Space 均可切换，状态与内容一致。
5. 关于、活动、档案、搜索兼容页和活动详情在 1440px 下居中且两侧有留白，在 360/390/430 下无横向溢出。
6. Header 搜索打开全屏搜索面板，输入“腾讯”能显示对应结果；Escape、关闭按钮和焦点恢复正确。
7. 无 JavaScript 时可通过 `/search/` 搜索兼容页访问搜索功能说明和索引入口，主要内容均可见。
8. NOTICE 明显大于当前版本，多行和多公告场景不溢出。
9. 首页所有主要访客文案均来自 `homepage.yml`、公告/活动/荣誉集合或站点设置；模板中只保留装饰标签。
10. 后台可添加多个友情链接，并能稳定选择一个或多个代码仓库链接；首页 GitHub 按钮指向真实 HTTPS 地址。
11. 页脚年份继续通过构建年份自动生成。
12. 访客页面不再出现迁移清单、待补充、上线核验等内部说明。
13. 公开页面不加载 Decap/Vditor/OAuth bundle；根路径与项目子路径构建均通过。

## 发现与证据

- 当前 `homepage.yml` 已有 Hero、简介和招募字段，但 `index.astro` 的实际大标题和多个章节文案仍然硬编码，后台修改不能覆盖所有可见内容。
- 当前友情链接确实是多项列表，不是单链接；但首页只通过 `links.find(/github/i)` 猜测 GitHub，而真实 GitHub 地址位于 `contact.yml`，导致开源按钮可能不显示。
- NOTICE 当前正文为 `0.85rem`、标签为 `0.65rem`，与用户反馈的“太小”一致。
- 当前 Footer 使用构建时年份，静态页面必须经过一次新构建才会跨年更新。
- 当前内页直接使用 `.section`，而新版 `.section` 只定义纵向间距、不定义内容宽度；这正是列表和详情贴近两侧的直接原因。

## 决策记录

- 搜索采用“全屏可访问搜索面板 + `/search/` 渐进增强兼容页”，不删除现有路由。
- 首页主要中文内容进入 CMS，装饰标签和动画参数留在代码。
- 友情链接维持多项列表，并增加语义用途字段；不再按显示名称猜测 GitHub。
- 动效以视觉等价和稳定帧率为目标，不逐行复制母版的废弃实验代码。
- 内部核验信息迁入文档，不以“临时提示”的方式展示给普通访客。

## 验证命令与结果

- 本轮仅编写开发文档，不修改运行时代码。
- 文档完成后执行 `git diff --check` 并检查明确暂存路径。
- 实现阶段必须执行：`npm run validate`、`npm run test:e2e`、项目子路径构建与 `validate:build`。

## 风险与回滚

- Canvas 动画可能增加移动端功耗；通过 DPR 上限、节点降级、页面隐藏暂停和减少动态偏好控制。
- CMS 字段扩展可能使旧 YAML 不满足 schema；必须在同一提交中先迁移默认内容并加验证。
- 搜索面板涉及焦点与滚动锁；必须覆盖 Escape、焦点恢复、无脚本和移动端键盘场景。
- 全站容器调整可能影响长图片和表格；逐页截图，不使用会破坏首页嵌套容器的全局宽度规则。
- 实现应形成独立本地提交；必要时可 revert 该提交恢复到视觉母版迁移提交 `6f240e1`。
