# 后台预览适配与首页集中编排（已完成）

## 目的与用户可见结果

原生 Decap 编辑器开启左右预览时不再被固定侧栏压缩；四个活动方向的文案和代表活动在“首页文案”同一处维护；成果时间轴可增删和拖动；首页管理摘要全部从实际数据计算。

## 范围与明确不做

调整后台壳层布局、`homepage.yml` / `homepage-featured.yml` 数据边界、CMS 配置、首页消费、后台内容索引、测试和文档。不改变四个活动方向的固定类别，不迁移活动或荣誉正文，不改认证和发布架构。

## 当前事实与相关文件

- `src/admin/admin.css` 在原生路由仍为固定侧栏预留 248px，双栏预览可用宽度不足。
- `src/data/homepage.yml` 保存活动方向文案，`src/data/homepage-featured.yml` 单独保存四个活动引用。
- `public/admin/config.yml` 将时间轴锁定为三项。
- `src/pages/admin/content-index.json.ts` 与 `src/admin/app-shell.tsx` 展示首页摘要，其中活动数量写死为 4。

## 验收标准

- 原生集合和编辑路由使用全宽内容区；新版导航以顶部入口打开覆盖式抽屉，不挤压编辑/预览。
- 每个固定活动方向对象同时包含类别、文案和同类别活动引用；旧的 featured 活动字段被安全迁移并删除。
- 时间轴至少保留一项，可新增、删除和拖动；首页按数据顺序渲染。
- 首页管理的公告、活动、荣誉数字来自内容索引实际数据。
- 桌面与移动后台、首页构建、schema 和相关测试通过。

## 分阶段步骤

1. 审核现有壳层与数据消费者，确定兼容迁移。
2. 修改 schema、YAML、CMS、首页和内容索引。
3. 修改后台布局与管理摘要。
4. 更新 `CONTENT_MODEL.md`、`ARCHITECTURE.md` 和 `PROGRESS.md`。
5. 完整校验、浏览器验收、提交并推送 `main`。

- 生产后台当前未登录视图仅显示 Decap 登录门，不暴露自定义壳层。

## 决策记录

- 原生 Decap 页面不保留桌面固定侧栏；统一使用 64px 顶部入口，导航抽屉覆盖页面。
- 内容编辑器返回集合根路由时按活动、首页、关于等归属恢复新版工作区；显式打开集合列表时不强制跳转。
- 四个方向仍固定，避免破坏前台四层交互；只把每个方向的代表活动引用与文案放入同一对象。
- 时间轴改为至少一项且以 YAML 列表顺序为唯一顺序源。
