# 后台可用性问题审查与微调

## 目的与用户可见结果

记录并修复维护者反馈的 8 个后台问题：未登录时必须先显示 Decap 登录页；原生编辑器和集合页不再被自定义侧栏遮挡或产生大片空白；移除无效的同步滚动；固定长度首页文案列表不允许新增；首页文案返回正确；首页文案与首页内容编排职责清晰且不能新增荣誉条目；排序只有一个明确生效来源；成员集合打开后立即可见管理选项。完成后从生产分支发布并做线上冒烟。

## 范围与明确不做

- 调整 React 后台壳层、Decap 配置、首页数据拆分、受版本保护的 Decap 补丁、自动化测试和维护文档。
- 保留 Decap CMS、Git 内容工作流、现有公开内容和 Cloudflare Pages 部署方式。
- 不删除活动、公告、成员、荣誉或图片；不修改真实 OAuth Secret；不替换 CMS。

## 当前事实与相关文件

- `src/admin/main.tsx` 在 `CMS.init()` 之前无条件挂载壳层；`src/admin/app-shell.tsx` 在空 hash 时主动进入 `#/manage/home`，因此未认证访问可看到自定义后台。
- `src/admin/admin.css` 为所有 Decap 原生页面增加 248px 左边距，同时保留固定自定义侧栏；这会挤压双栏编辑器，并与集合页自身布局叠加。
- `public/admin/config.yml` 的首页固定数组只设置 `min/max`，仍显示新增按钮；老师、链接、页脚和联系方式同时允许拖动又提供 `order`。
- `src/data/homepage.yml` 同时保存页面文案和首页内容引用，导致“编辑首页文案”暴露公告、活动与荣誉编排。
- Decap Core 3.17.1 的同步滚动按钮来自 `EditorInterface.js`，现有安装补丁脚本已经具备精确版本和目标文本保护。

## 验收标准

1. 清空认证状态访问 `/admin/` 或任意 `#/manage/...` 时，自定义壳层不可见，登录按钮立即可见；登录成功后才进入首页管理。
2. 活动编辑器在 1440px 桌面视口中完整显示左侧表单与右侧预览，不被自定义侧栏覆盖；移动端无页面级横向溢出。
3. 编辑器不再显示“同步滚动”按钮，左右区域可独立滚动。
4. 三项原则、四个活动方向、三项成果时间轴、三个加入路径均不显示新增、删除或拖动控件。
5. 从首页管理进入“编辑首页文案”后点击 Decap 返回，回到首页管理，不进入全站设置。
6. 首页文案编辑器只编辑访客文案；公告、四个活动位、三项荣誉在独立“首页展示编排”中仅引用已有条目，荣誉固定三项且不能新增或删除。
7. 老师、相关链接、页脚链接、联系方式以数字 `order` 为唯一排序依据，列表拖动关闭且字段帮助说明“数字越小越靠前”；成员集合继续以成员 `order` 为唯一依据。
8. “管理全部成员”打开后首屏即可看到 Decap 集合工具和成员列表，无自定义布局造成的大片空白。
9. 类型、单元、内容、构建、常规 E2E、本地 CMS E2E 均通过；桌面和 390px 浏览器验证无控制台错误。

## 分阶段步骤

1. 记录问题并审查登录、路由、布局、数据模型和排序消费者。
2. 让壳层订阅 Decap 认证状态；原生路由使用完整 Decap 布局；修复设置条目返回上下文。
3. 将首页内容引用迁到独立数据文件和独立设置条目；锁定固定列表；明确排序规则。
4. 扩展受版本保护的 Decap 补丁以移除同步滚动控件并默认独立滚动。
5. 更新测试和文档，执行完整验证和桌面/移动视觉检查。
6. 自包含提交，合并到 `main`、推送并验证 Cloudflare Pages 生产结果。

## 发现与证据

- Decap Redux `auth.user` 在认证完成前为 `undefined`、未登录为 `null`、登录后为用户对象，可作为壳层唯一显示门槛，无需通过 DOM 观察推断登录状态。
- Decap 列表控件使用 `allow_add`、`allow_remove`、`allow_reorder`；项目此前未配置后二者。
- 前台在 `src/lib/site.ts` 明确按 `order` 数字排序老师、链接、联系方式和页脚链接，说明拖动顺序当前不会生效。
- 首页设置条目的 Decap 原生返回目标是 `#/collections/settings`，自定义路由把它解释为“全站设置”，需要依据刚离开的设置条目恢复对应管理页。
- 原生路由出现大片空白的直接原因还包括：自定义壳层子节点虽隐藏，`.admin-shell` 仍保留 `min-height: 100vh`，把后置的 `#nc-root` 整体向下推了一个视口；原生路由现将壳层高度归零。

## 决策记录

- 认证门采用 Decap Redux 状态订阅，不读取本地 Token、不观察 DOM，也不复制 OAuth 逻辑。
- 自定义壳层只用于六个管理工作区；进入 Decap 集合或编辑器时让原生后台占满视口，避免两个导航系统抢占同一布局。
- 页面文案与首页展示编排拆分为两个 YAML 文件；前者不再出现公告、活动和荣誉字段，后者只保存稳定 ID 引用。
- 对带 `order` 的 YAML 列表关闭拖动，保留数字为唯一排序源；固定位置数组同时关闭新增、删除和拖动。
