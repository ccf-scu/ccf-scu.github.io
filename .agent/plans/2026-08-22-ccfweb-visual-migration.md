# 将 ccfweb 视觉母版迁移到 Astro 正式站

## 目的与用户可见结果

以相邻目录 `../ccfweb` 的页面为视觉母版，保留其“深色知识场 + 白色编辑页面 + 深色档案/加入章节”的整体叙事、排版和组件语言，同时继续使用当前 Astro 内容、CMS、路由和静态构建体系。完成后首页应在桌面与移动端明显接近 ccfweb，而活动、详情、关于、档案和搜索页共享同一套视觉模板。

## 范围与明确不做

- 分析并记录 ccfweb 的设计 token、版式、组件、动效、响应式和无障碍规则。
- 重构公开站点的 Header、Footer、首页、列表/详情和通用 CSS。
- 保留现有 Markdown/YAML、Decap/Vditor、URL、搜索与分享功能。
- 不逐字复制 ccfweb 的硬编码内容，不引入报名后端，不恢复未使用的旧 CSS，也不把 CMS bundle 带到前台。
- 不 push、不部署、不修改生产分支或外部服务。

## 当前事实与相关文件

- 视觉来源：`../ccfweb/index.html`、`styles.css`、`script.js`、桌面/移动截图。
- 正式实现：`src/layouts/BaseLayout.astro`、`src/components/`、`src/pages/`、`src/styles/global.css`。
- 现有内容与功能已在提交 `3a80297` 完成，本次只迁移视觉模板及必要的渐进增强交互。
- 详细分析与迁移映射见 `docs/CCFWEB_VISUAL_MIGRATION.md`。

## 验收标准

- 首页保留 ccfweb 的深色共振 Hero、编辑式 About、深色活动仪表、深色档案、浅色开源卡片和深色 Join 结尾。
- 通用页面使用同一字体、颜色、容器、章节编号、卡片和响应式语法。
- 360/390/430 和桌面无横向溢出、遮挡或缺图；菜单、活动切片、筛选、搜索、分享和成员展开可用。
- 减少动态偏好下关闭非必要动效；无 JavaScript 时仍有完整内容。
- 公开页面不请求 Decap/Vditor；全量检查、根路径/子路径构建和浏览器测试通过。

## 分阶段步骤

1. 对 ccfweb 做视觉与代码审计，建立迁移规范。
2. 重构全局 token、Header、Footer 和页面通用骨架。
3. 以内容数据重建 ccfweb 风格首页及轻量交互。
4. 统一活动、详情、关于、档案、搜索等内页。
5. 完成自动检查、浏览器截图对照、文档与提交。

## 发现与证据

- ccfweb 的核心不是单个卡片，而是黑/白章节交替、超大无衬线标题、单一电蓝强调色和技术微排版构成的连续叙事。
- 母版 CSS 约 8 千行，包含多轮废弃原型；不能整体复制，应迁移最终生效的视觉规则和当前 HTML 使用的组件。
- Hero 的 Canvas 与活动拖拽是增强层；其静态构图本身必须先成立。

## 决策记录

- 采用“视觉等价、架构原生”迁移：Astro 继续负责数据与 HTML，只移植设计系统和必要交互。
- 首页保留母版章节顺序，当前活动/荣誉内容动态填充，不回退到硬编码档案。
- Canvas 共振场改为轻量 CSS/指针能量增强，避免复制上千行实验性脚本；活动切片保留按钮/键盘切换。
- Reveal 不作为内容可见性的前置条件；公开正文默认展示，避免低性能设备、打印与自动截图出现空白章节。

- `npm run test:e2e`：10 项通过；覆盖桌面、360/390/430、主要内页、活动切片/筛选、搜索、成员展开、分享、二维码和后台外壳。
- `git diff --check`：通过。
- 人工对照 `../ccfweb/preview-desktop.png`、`preview-mobile.png` 与 `artifacts/visual-validation/` 截图；黑白章节、标题比例、活动仪表、档案卡与移动布局符合迁移规范。
