# 执行计划规范

复杂功能、重大重构和迁移使用 ExecPlan。计划应让不了解此前对话的开发者仅凭仓库内容继续工作。

## 必需章节

```markdown
# <目标>

## 目的与用户可见结果
## 范围与明确不做
## 当前事实与相关文件
## 验收标准
## 分阶段步骤
## 进度（带时间）
## 发现与证据
## 决策记录
## 验证命令与结果
## 风险与回滚
## 未完成项与下一步
```

## 编写要求

- 自包含：写清路径、术语、前置条件和命令；
- 面向结果：每阶段给出可观察出口，不只列编码动作；
- 持续更新：完成步骤、发现、失败和决定及时写回；
- 诚实验证：区分已实现、已验证、未验证和延期；
- 可恢复：说明不会触碰的资产、备份点和回滚方式；
- 不复制整份架构文档，用链接引用稳定信息；
- 计划不是授权，不扩大用户允许的发布、删除或外部写入范围。

单次任务计划放在 `.agent/plans/<yyyy-mm-dd>-<slug>.md`。完成后保留为执行记录，必要时在顶部标为完成或被替代。
