# 测试与验收

## 原则

- 根据风险选择检查，不用单一“构建通过”替代真实验证；
- 前端变更必须在浏览器中验证目标流程；
- 失败和未执行项必须如实记录；
- 原型通过不代表正式仓库、真实 OAuth 或生产域名通过。

## 计划中的自动检查

阶段 1 应在 `package.json` 和 CI 中提供：

- 格式检查；
- Astro/TypeScript 类型检查；
- 内容 schema 校验；
- 单元测试（状态、排序、URL、过滤等纯函数）；
- 静态构建；
- 内部链接、资源和错误 base path 扫描；
- 超大图片和缺失替代文本检查；
- 必要的依赖审计记录。

最终命令以 `package.json` 为准，并同步更新 `DEVELOPMENT.md`。

## 浏览器验证

每个 UI 任务先写目标流程，例如：`首页 -> 打开移动导航 -> 点击活动 -> 正确到达活动详情`。

至少检查：

1. URL 和页面标题正确；
2. 页面有真实内容且无框架错误覆盖层；
3. 控制台无相关 error/warn；
4. 完成至少一个目标交互并验证结果；
5. 截图证明关键视觉结论；
6. 桌面和移动视口均验证；
7. 动画页面验证 `prefers-reduced-motion`。

优先使用环境提供的 Browser 工具；不可用时使用仓库 Playwright 流程，并记录采用的路径。临时截图、trace 和调试脚本不进入仓库，除非明确作为测试 fixture 审批。

## 移动端矩阵

重点宽度：360、390、430、768、1024 px；页面：首页、活动列表、活动详情、成员简介、搜索、后台。

检查页面级横向溢出、导航滚动锁、触控目标、长标题、表格、代码、长 URL、图片裁切、二维码、软键盘和中文输入。至少补充一次真实手机或可信设备模拟截图验收。

## 内容与 CMS

- 活动三个时间状态；
- `endAt < startAt` 被拒绝；
- 首页置顶、显隐和数量；
- 公告到期；
- 草稿不公开；
- Vditor 保存/重开无格式损失；
- 仓库图片和外部 HTTPS 图片；
- 双维护者顺序编辑、冲突、审核、发布、归档和回滚。

## 上线硬门禁

必须完成 OAuth 最小权限、CMS 全闭环、多人演练、图片优化、Vditor 回退、360/390/430 验收、国内常用网络实测、分支保护、备份和恢复演练。Cloudflare Pages 不是首期硬门禁。
