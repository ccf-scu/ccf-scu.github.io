# 故障与回滚手册

## 先判断影响

- 只有后台登录失败：暂停内容发布，公众站继续运行，使用 GitHub 内容 PR 应急；
- 单条内容错误：归档或 revert 对应内容 commit；
- 新站页面/资源错误：停止发布，revert 上线合并 commit，重新部署上一可用版本；
- 账号或 Secret 疑似泄漏：立即撤销 Token/App 权限并轮换 Secret，保存日志，再调查仓库和个人信息影响。

## 回滚步骤

1. 记录发现时间、页面、截图、当前生产 commit 和影响范围；
2. 暂停 CMS 发布与部署，不在生产分支直接试改；
3. 由两名维护者确认目标可用 commit；
4. 创建 revert PR，等待必需检查通过后合并；
5. 验证首页、活动、后台入口、静态资源和旧 URL；
6. 记录恢复时间、执行人、根因和后续措施。

不得通过删除 Git 历史、强推或上传来源不明的 `dist` 恢复。涉及隐私或凭据时，不在公开 Issue 粘贴细节。
