# CMS 与前台字段对照及换届操作指南

本文是后台维护者的操作契约。后台字段保存后会进入 Git 内容工作流；合并并完成生产构建后，前台才会更新。

## 结论与改进清单

| 后台内容 | 前台位置 | 当前规则 |
|---|---|---|
| 活动：首页优先 | 首页活动区、活动列表 | 仅在“首页显示”开启且未归档时生效；同一方向优先选择该项，活动列表也优先排序 |
| 活动：首页显示 | 首页活动区 | 关闭后不会成为首页代表活动，但仍保留在活动列表 |
| 活动：归档/下架 | 全站 | 开启后从活动列表和首页移除，文件保留 |
| 公告：置顶/显示/失效时间 | 首页 NOTICE | 仅展示已发布、可见且未失效项；置顶优先，数量由首页设置控制 |
| 荣誉：首页精选 | 首页成果卡、历史档案 | 首页精选优先，历史档案展示全部可见项 |
| 指导老师 | 关于分会 | 仅展示“显示”开启的老师，按排序升序 |
| 友情链接：普通链接 | 关于分会 | 展示在“相关链接”区 |
| 友情链接：代码仓库 | 首页开源区 | 按排序选取第一个可见项 |
| 友情链接：页脚链接 | 关于分会、全站页脚 | 两处均显示 |
| 联系方式（含 QQ 群） | 关于分会、全站页脚 | 可在后台直接修改显示值、链接、排序和显隐 |
| 成员 | 关于分会、历史档案、搜索 | 本届由分会信息的“本届执委届次”指定；所有可见届次自动进入历史档案 |

## 换届操作

1. 在“成员”中新建新一届成员，每一条的“届次”填写完全相同的文本，例如 `第十六届（2026–2027）`。
2. 设置姓名、职务和排序；确认可公开后开启“显示”。个人简介只有同时开启“简介已获确认”才公开。
3. 先发布这些成员，并确认历史档案自动出现新的届次标题和成员组。
4. 打开“站点设置 → 分会信息”，把“本届执委届次”改为同一文本，再发布。
5. 确认“关于分会”已切换到新一届。旧成员不删除、不隐藏，继续保留在历史档案。

构建校验会拒绝不存在于成员记录中的“本届执委届次”，避免拼写差异导致本届区域为空。

## 正文编辑器故障降级

Vditor 保存标准 Markdown。编辑器初始化失败时，后台显示原生 Markdown 文本框，内容仍可编辑和保存。离开编辑页时只销毁已经完成初始化的实例，避免初始化与路由切换竞态触发 `Cannot read properties of undefined (reading 'element')`。

## 发布后检查

- 活动：首页对应方向、活动列表顺序、详情正文；
- 组织：关于页的指导老师、本届执委、相关链接和联系方式；
- 换届：历史档案新增届次标题，旧届次仍存在；
- 全站：页脚 QQ 群或其他联系方式已更新；
- 后台：进入带正文的活动或成员，编辑器可见，返回列表无错误覆盖层。
