# 旧站迁移

## 原则

迁移是“提取、校验、人工确认、再发布”，不是直接复制旧 HTML。旧 `main` 在切换完成前保持可恢复。

## 已知资产

- 约 28 条活动记录；
- 15 届执委、约 203 个成员卡片；
- 指导老师、荣誉、品牌和联系方式；
- 图片目录约 139 MB，其中存在 8–18 MB 原图；
- 旧首页、活动、历届执委和团队建设路径。

具体数量以迁移脚本生成的 manifest 为准，不把估算写成验收结果。

## 流程

1. 只读解析旧 HTML 和图片目录；
2. 输出带来源路径、哈希和缺失字段的 manifest；
3. 去重并抽样确认字段映射；
4. 生成 Markdown/YAML 草稿；
5. 图片哈希去重、方向修正、压缩样张和授权检查；
6. 人工复核标题、日期、分类、成员和图片；
7. 建立旧 URL 到新 URL 映射；
8. CI 构建全部迁移内容；
9. 内容负责人确认后纳入生产。

## 禁止事项

- 不根据页面上下文猜测个人简介或敏感资料；
- 不因压缩而覆盖唯一原图；
- 不把全部活动相册无筛选塞入仓库；
- 不重命名已公开 slug 而不记录兼容路径；
- 不直接在生产分支运行迁移脚本；
- 不删除旧资产直到备份和上线观察期结束。

## 迁移证据

`scripts` 最终应产生可提交的内容 manifest、URL 映射和异常清单。生成日志、临时解压目录和重复的转换输出不提交；经人工确认的 manifest、映射和必要校验报告必须提交。
