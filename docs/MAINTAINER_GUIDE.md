# 非技术维护手册

## 日常发布

1. 打开网站 `/admin/`，使用获授权且启用 2FA 的 GitHub 账号登录；
2. 选择活动、公告、成员或站点设置，新建或修改内容；
3. 完成所有必填项，图片填写准确替代文本，正文不要粘贴脚本或不明网页组件；
4. 保存为草稿，打开预览检查手机与电脑效果；
5. 请另一名维护者核对事实、隐私和图片授权；
6. 审核后发布，等待检查通过，再访问公众页面确认；
7. 记录内容标题、时间、发布者和审核者。

## 活动状态

- 尚未开始、进行中、已结束由开始/结束时间自动计算；
- 内容不再展示时使用“归档”，不要物理删除；
- 置顶仅用于少量重要活动，避免长期全部置顶；
- 外部链接只使用可信的 `https://` 地址。

## 图片

优先上传清晰且已获授权的 JPG、PNG 或 WebP；封面建议 3:2。不要上传群聊截图、身份证件、联系方式清单、未经授权的人像或超大原图。替代文本描述画面本身，例如“嘉宾在讲台分享开源项目”，不写“图片”。

## 后台故障时

公众网站与后台相互隔离，后台故障通常不会影响浏览。联系技术维护者通过 GitHub 创建内容 PR；不要共享账号、Token 或 OAuth Secret，也不要直接改 `dist/`。具体处置见 `INCIDENT_ROLLBACK.md`。

## 换届

按 `HANDOVER_CHECKLIST.md` 增加新维护者、演练发布与回滚，再撤销离任人员权限。始终保留至少两名可工作的维护者。
