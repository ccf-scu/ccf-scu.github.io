# CMS 与编辑流程

## 页面化后台与图片中心

登录成功后，后台固定为“首页管理、活动页面、关于与档案、全站设置、待发布、图片中心”六个一级页面。未登录时只显示 Decap 登录界面，不渲染管理壳层。桌面端自定义工作区使用左侧导航，移动端使用顶部按钮唤出的导航抽屉；进入具体 Decap 集合或编辑器后使用完整原生布局，返回时恢复所属管理页。首页管理集中展示公告顺序、四方向活动位和三项荣誉；活动条目中的“活动中心置顶”只影响活动列表。

图片中心是正式一级页面，也是维护者可见的唯一图片入口。页面可浏览、筛选和搜索已发布内容引用的共享图片，查看详情和引用数量、复制 URL，并在默认收起的设置区配置当前浏览器的通用 `multipart/form-data` HTTPS 图床。普通图片字段通过“从图片中心选择”打开共享选择器。配置包含接口、文件字段、认证 Header 和响应 URL 路径；Token 默认只保留到当前会话结束。图床必须支持浏览器 CORS。图片中心不会删除或重命名远程文件。

## 范围

Decap CMS 管理首页、活动、公告、成员、指导老师、友情链接、招新和联系方式。首页不是自由页面搭建器；后台只能编辑开发者提供的字段、顺序和显隐。

## 首页与链接维护

- 在“首页管理 → 编辑首页文案”只维护 Hero、分会介绍、活动方向、成果时间轴、开源和招募文案；三项原则、四个活动方向、三项时间轴和三个加入路径是固定结构，不提供新增、删除或拖动；
- 在“首页管理 → 调整首页展示”只选择已有公告、四方向代表活动和三项已有荣誉，不在该入口新建或编辑内容条目；三项荣誉可拖动改变首页顺序，但不能新增或删除；
- 活动图片、标题和日期继续在“活动”集合维护，荣誉卡在“荣誉与成果”集合维护，NOTICE 在“公告”集合维护；
- 在“关于与档案 → 相关链接”维护关于页链接，只需填写名称、网址、排序和显隐，不再选择类型或用途；
- 指导老师、相关链接、页脚链接、联系方式和成员均以“显示顺序”数字为准，数字越小越靠前；带数字排序的 YAML 列表不再允许拖动；
- “全站设置”分别维护首页开源按钮和页脚外链；
- 相关链接、开源按钮和页脚外链接受完整的 HTTP 或 HTTPS 地址，优先使用 HTTPS；其他协议会被拒绝。站内按钮路径仍以 `/` 开头。

## 登录和授权

- 正式后台为 `https://www.ccfscu.com/admin/`；右上角“返回前台”始终使用当前访问域名，不依赖配置中的固定域名；
- 使用 GitHub 账号；
- OAuth 辅助服务仅交换授权，不保存内容；
- GitHub App/OAuth 权限限制到 `ccf-scu/ccf-scu.github.io`；
- Secret 只存外部运行环境的秘密存储；
- 至少两名维护者完成真实登录演练后才能上线后台。

若保存时出现 `organization has enabled OAuth App access restrictions`，说明登录成功但组织拒绝该 OAuth App 写仓库。维护者需在个人 GitHub 的 Authorized OAuth Apps 页面请求 `ccf-scu` 访问，随后由组织所有者在 `Organization Settings → Third-party Access → OAuth app policy` 中对 `CCF SCU CMS` 执行 `Review → Grant access`。批准后退出后台并重新登录。此限制不能由前端或 OAuth Worker 绕过，也不应通过关闭组织安全策略规避。

`config.yml` 的 `base_url` 指向独立 Cloudflare Worker 的 OAuth 地址；`api_root` 指向自有域名 `https://cms-api.ccfscu.com/github` 下的受限代理，避免客户端网络拦截 `workers.dev` 或直接提交 GitHub 二进制媒体时只出现无状态码的 `Failed to fetch`。代理只接受正式后台来源，并且只允许访问本站仓库与当前用户接口。Worker 源码、部署参数、回调地址和轮换方式见 [`../infrastructure/oauth-worker/README.md`](../infrastructure/oauth-worker/README.md)，架构决策见 [`decisions/0002-cloudflare-worker-oauth.md`](decisions/0002-cloudflare-worker-oauth.md)。只有两项 GitHub 凭据均进入 Cloudflare 加密 Secret、真实登录通过且构建产物中不存在 Secret 后，后台才可视为可发布。

## 编辑工作流

1. 新建或打开内容；
2. 保存草稿，生成内容分支；
3. 查看静态预览；
4. 线下约定的审核者检查内容；
5. 在后台发布并触发合并/构建；
6. 检查生产页面；
7. 需撤回时归档或 revert，不物理删除。

所有维护者可以编辑和审核发布，但同一内容一次只由一人编辑。发生冲突时停止覆盖，由维护者比较 Git diff 后决定保留版本。

## 成员介绍

- “执委成员 → 弹窗个人介绍”保存标准 Markdown，可写多段文字，也可通过 Decap 原生编辑器插入图片；
- 前台点击执委卡片后，在高于当前页面的介绍框内显示姓名、职务、届次和正文；关闭后焦点返回原卡片；
- 只有“简介已获确认”开启后才公开正文，未确认内容继续显示占位提示；照片和正文图片发布前均需完成本人或负责人确认。

## Markdown 编辑器契约

- 使用 Decap 内置 `markdown` widget，不维护第三方编辑器适配层；
- 保存标准 Markdown，不保存专有编辑器 JSON；
- 支持中文输入、标题、列表、链接、表格、代码和图片；
- 清理危险 HTML 和脚本协议；
- 复杂编辑以桌面端为主，手机支持应急短改。

项目已移除 Vditor 依赖、自定义控件和动态 CDN 资源，正文编辑与预览均由 Decap 提供，因此不会再请求 unpkg。由于真实仓库媒体写入依赖 OAuth 后端，保存重开、媒体库和正文图片上传属于上线前人工硬门禁。

Decap Core 3.17.1 的媒体库顶部组件在尚未选择文件时会错误读取 `selectedFile.path`。仓库通过 `postinstall` 运行受版本保护的小补丁，将该读取改为空值安全访问；升级 Decap Core 时必须先复核并删除或更新此补丁，禁止无提示跳过。

## 图片

- 封面、Logo、成员/老师照片、二维码和精选正文图进入仓库；
- 大量相册可引用经批准的 HTTPS 图床；
- 禁止 GitHub Raw、聊天临时链接和维护归属不明的免费图床；
- 上传前校验类型和体积，构建时生成响应式尺寸；
- 图片插入必须要求替代文本；
- 图片处理失败应阻断内容发布而不是静默使用超大原图。

## 防误操作

- 必填、枚举、日期关系和 URL 在 CMS 与 CI 双重校验；
- 默认隐藏物理删除操作；
- 草稿不进入生产、搜索索引和 sitemap；
- 发布前提供预览；
- 每次发布保留 commit；
- 后台配置、OAuth 和上传必须在隔离环境先验证。

## 应急更新

当 CMS/OAuth 暂时不可用时，技术维护者可在 GitHub 网页编辑相应 Markdown/YAML、创建 PR、等待检查通过后合并。不得绕过 schema 直接编辑生成产物。
