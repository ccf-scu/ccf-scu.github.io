# CMS 与编辑流程

## 范围

Decap CMS 管理首页、活动、公告、成员、指导老师、友情链接、招新和联系方式。首页不是自由页面搭建器；后台只能编辑开发者提供的字段、顺序和显隐。

## 首页与链接维护

- 在“站点设置 → 首页设置”维护 Hero、分会介绍、活动方向、成果时间轴、开源和招募文案；三项原则、四个活动方向和三项时间轴/加入路径必须保持固定数量；
- 活动图片、标题和日期继续在“活动”集合维护，荣誉卡在“荣誉与成果”集合维护，NOTICE 在“公告”集合维护；
- 在“站点设置 → 友情链接”可连续添加多项。普通站点选择 `general`，代码仓库选择 `repository`，页脚专用链接选择 `footer`；
- 首页开源按钮使用排序最前且可见的 `repository` 链接，因此仓库名称可以自由修改；URL 必须为 HTTPS；
- 保存前检查按钮路径。站内链接以 `/` 开头，外链只接受 HTTPS。

## 登录和授权

- 使用 GitHub 账号；
- OAuth 辅助服务仅交换授权，不保存内容；
- GitHub App/OAuth 权限限制到 `ccf-scu/ccf-scu.github.io`；
- Secret 只存外部运行环境的秘密存储；
- 至少两名维护者完成真实登录演练后才能上线后台。

`config.yml` 的 `base_url` 指向独立 Cloudflare Worker。Worker 源码、部署参数、回调地址和轮换方式见 [`../infrastructure/oauth-worker/README.md`](../infrastructure/oauth-worker/README.md)，架构决策见 [`decisions/0002-cloudflare-worker-oauth.md`](decisions/0002-cloudflare-worker-oauth.md)。只有两项 GitHub 凭据均进入 Cloudflare 加密 Secret、真实登录通过且构建产物中不存在 Secret 后，后台才可视为可发布。

## 编辑工作流

1. 新建或打开内容；
2. 保存草稿，生成内容分支；
3. 查看静态预览；
4. 线下约定的审核者检查内容；
5. 在后台发布并触发合并/构建；
6. 检查生产页面；
7. 需撤回时归档或 revert，不物理删除。

所有维护者可以编辑和审核发布，但同一内容一次只由一人编辑。发生冲突时停止覆盖，由维护者比较 Git diff 后决定保留版本。

## 成员介绍

- “成员 → 弹窗个人介绍”保存标准 Markdown，可写多段文字，也可通过 Vditor 插入图片；
- 前台点击执委卡片后，在高于当前页面的介绍框内显示姓名、职务、届次和正文；关闭后焦点返回原卡片；
- 只有“简介已获确认”开启后才公开正文，未确认内容继续显示占位提示；照片和正文图片发布前均需完成本人或负责人确认。

## Vditor 契约

- 以 Decap 自定义 widget 接入，不修改 Decap 内核；
- 保存标准 Markdown，不保存专有编辑器 JSON；
- 支持中文输入、标题、列表、链接、表格、代码和图片；
- 清理危险 HTML 和脚本协议；
- 编辑器加载失败时回退到 Markdown 文本框；
- 复杂编辑以桌面端为主，手机支持应急短改。

当前代码已注册 Vditor 自定义控件并提供普通 Markdown 文本框回退。由于真实仓库媒体写入依赖 OAuth 后端，保存重开、媒体库和正文图片上传属于上线前人工硬门禁。

## 图片

- 封面、Logo、成员/老师照片、二维码和精选正文图进入仓库；
- 大量相册可引用经批准的 HTTPS 图床；
- 禁止 GitHub Raw、聊天临时链接和维护归属不明的免费图床；
- 上传前校验类型和体积，构建时生成响应式尺寸；
- 图片插入必须要求替代文本；
- 图片处理失败应阻断内容发布而不是静默使用超大原图。

## 防误操作

- 必填、枚举、日期关系和 URL 在 CMS 与 CI 双重校验；
- 默认隐藏物理删除操作；
- 草稿不进入生产、搜索索引和 sitemap；
- 发布前提供预览；
- 每次发布保留 commit；
- 后台配置、OAuth 和上传必须在隔离环境先验证。

## 应急更新

当 CMS/OAuth 暂时不可用时，技术维护者可在 GitHub 网页编辑相应 Markdown/YAML、创建 PR、等待检查通过后合并。不得绕过 schema 直接编辑生成产物。
