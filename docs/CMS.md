# CMS 与编辑流程

## 范围

Decap CMS 管理首页、活动、公告、成员、指导老师、友情链接、招新和联系方式。首页不是自由页面搭建器；后台只能编辑开发者提供的字段、顺序和显隐。

## 登录和授权

- 使用 GitHub 账号；
- OAuth 辅助服务仅交换授权，不保存内容；
- GitHub App/OAuth 权限限制到 `ccf-scu/ccf-scu.github.io`；
- Secret 只存外部运行环境的秘密存储；
- 至少两名维护者完成真实登录演练后才能上线后台。

## 编辑工作流

1. 新建或打开内容；
2. 保存草稿，生成内容分支；
3. 查看静态预览；
4. 线下约定的审核者检查内容；
5. 在后台发布并触发合并/构建；
6. 检查生产页面；
7. 需撤回时归档或 revert，不物理删除。

所有维护者可以编辑和审核发布，但同一内容一次只由一人编辑。发生冲突时停止覆盖，由维护者比较 Git diff 后决定保留版本。

## Vditor 契约

- 以 Decap 自定义 widget 接入，不修改 Decap 内核；
- 保存标准 Markdown，不保存专有编辑器 JSON；
- 支持中文输入、标题、列表、链接、表格、代码和图片；
- 清理危险 HTML 和脚本协议；
- 编辑器加载失败时回退到 Markdown 文本框；
- 复杂编辑以桌面端为主，手机支持应急短改。

## 图片

- 封面、Logo、成员/老师照片、二维码和精选正文图进入仓库；
- 大量相册可引用经批准的 HTTPS 图床；
- 禁止 GitHub Raw、聊天临时链接和维护归属不明的免费图床；
- 上传前校验类型和体积，构建时生成响应式尺寸；
- 图片插入必须要求替代文本；
- 图片处理失败应阻断内容发布而不是静默使用超大原图。

## 防误操作

- 必填、枚举、日期关系和 URL 在 CMS 与 CI 双重校验；
- 默认隐藏物理删除操作；
- 草稿不进入生产、搜索索引和 sitemap；
- 发布前提供预览；
- 每次发布保留 commit；
- 后台配置、OAuth 和上传必须在隔离环境先验证。

## 应急更新

当 CMS/OAuth 暂时不可用时，技术维护者可在 GitHub 网页编辑相应 Markdown/YAML、创建 PR、等待检查通过后合并。不得绕过 schema 直接编辑生成产物。
